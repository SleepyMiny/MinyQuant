# MinyAI 연결 계약

MinyAI는 계획·기억·공통 UI·권한 전달·서비스 상태를 담당하고, MinyQuant는 시장·전략·위험·주문·계좌 원장·대사·활성화를 소유한다. 이 문서는 외부 검토자가 읽을 수 있는 공개 연결 계약이다. MinyAI의 구현·배포·개인 설정은 비공개로 유지하며, 공개 계약 버전에 맞춰 코어 T10과 함께 개발한다. 현재 실제 API 구현은 없다.

- MinyQuant는 독립 개발·배포한다. MinyAI 내부 패키지·DB에 직접 의존하지 않고 계약 버전과 호환 범위를 명시한다.
- 서비스 ID, capability, 계약 버전, 상태를 등록한다. 등록 자체가 권한 부여는 아니다.
- 요청에는 request ID·중복 방지 키·기한·action·대상·입력·대상 서비스로 제한된 위임 참조를 둔다. 승인된 인자와 다른 주문으로 바꿀 수 없다.
- MinyQuant가 권한을 검증하고 자신의 더 엄격한 정책으로 거절할 수 있다. 승인 소비·현금/노출 예약·의도는 금융 DB 하나의 트랜잭션으로 처리한다. 코어에서 같은 승인을 따로 소비하지 않는다.
- 접수·진행·완료·실패·취소·UNKNOWN과 근거·시각을 조회/이벤트로 전달한다. 응답 유실 시 같은 요청 ID로 조회하며 새 ID로 맹목적으로 재주문하지 않는다.
- 코어 연결 중단 중에도 내부 대사·안전 중지는 유지한다. 신규 위험 확대는 승인/위임·heartbeat 신선도 규칙을 따른다. 코어 미설치와 내부 연구·fake 시험 가능 여부는 구분한다.
- 금융 데이터/키는 MinyQuant가 소유한다. MinyAI에는 필요한 요약·상태만 반환하고 계좌 식별정보·원본 자료를 생활 기억에 자동 적재하지 않는다.
- fake 서비스와 fake 코어로 버전 불일치·권한 초과·응답 유실·중복/역순 이벤트·취소 경쟁을 양쪽에서 검증한 뒤 실제 연결한다.
