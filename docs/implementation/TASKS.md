# MinyQuant 작업 카드

Q00은 이 저장소의 시작 작업이다. T06/T09는 기존 추적 ID를 유지한다. 모두 TODO이며 외부 계정/실거래 준비가 완료됐다는 의미가 아니다.

<a id="q00"></a>
## Q00 — 독립 개발 기준선

- 입력: 현재 저장소와 금융 설계. MinyAI 구현이나 실제 계좌가 필요하지 않다.
- 산출물: 루트 Python 패키지 설정, `src/minyquant/`, `tests/`, 재현 가능한 의존성·검증 명령. 실제 필요한 파일부터 만든다.
- 검증: 선택한 환경에서 설치/import와 첫 도메인 계약/합성 fixture 시험. 유료 공급자·실제 브로커에 연결하지 않고 재현 가능해야 한다.
- 완료 증거: 환경·명령·결과·CI 도입 여부를 STATUS에 기록하고 T06으로 진행한다. 문서 이전 검사를 런타임 시험으로 대신하지 않는다.

<a id="t06"></a>
## T06 — 국내외 시장 연구·모의 실행

- **상태/입력:** TODO / 주식 도메인 계약. 오프라인 연구·브로커 fake는 독립 개발하며 실제 MinyAI 연결은 코어의 T10과 [연결 계약](../integration/minyai.md) 검증에 의존한다.
- **경로:** 별도 저장소의 제안 `src/minyquant/marketdata/`, `src/minyquant/{instruments,risk,execution,reconciliation,brokers}/`, `tests/test_trading_scenarios.py`, 합성 시장 fixture.
- **할 일:** 종목/거래소/통화/세션/달력/시각/환율 공통 계약을 정의하고 첫 구현은 한 broker adapter·한 시장으로 제한한다. 원문 입수시각과 정정 이력, 시간순 검증, 비용/슬리피지를 반영한다. 금융 DB 안에서 승인 소비/위임 차감·한도 검사·현금/노출 예약·주문 의도 저장을 원자적으로 처리한 뒤 계좌별 단일 실행과 체결/잔고 대사를 수행한다. UNKNOWN·부분체결·취소 경쟁·손실한도·수동 변경을 처리한다. 사고 중지는 영속 latch로 남기고 재시작·날짜 변경·대사 성공만으로 해제하지 않는다. LLM은 실행 키를 받지 않는다.
- **검증:** fake 브로커로 중복/역순/누락, 응답 유실, 동시 현금 예약, 데이터 만료, 시간 오차, 환전, DB 복원, 이중 executor, 비상 중지를 시험한다. 실제 모의 연결은 공급자 지원/권한/한도 설정 후 별도 증거로 남긴다. 20일 등 기간이나 단일 수익률을 통과 조건으로 삼지 않는다.
- **완료 증거:** 재현 데이터/전략 버전, 위험 불변식·대사 테스트, 미해결 주문 목록, 실제 모의 환경 결과와 한계. 계좌 미연결이면 오프라인 검증 완료와 실제 모의 미검증을 분리하고 T09 진입 조건을 충족했다고 표시하지 않는다.
- **차단 범위:** 증권사/키/실제 자금 미정이어도 합성 fixture·fake 구현을 진행한다. 실전 키 배포·실주문·임의 환전·실전 자동 재개는 포함하지 않는다.


<a id="t09"></a>
## T09 — 제한된 소액 실전 활성화

- **상태/입력:** TODO / 주식 저장소의 연구·모의·위험/대사 검증, 실제 모의 결과, 업데이트·키 분리·복원·대사·비상 중지, 사용자가 확정한 계좌/시장/전략/자금/주문/노출/손실/기간 한도. 음성·스마트홈은 선행 조건이 아니다.
- **경로:** T06의 기존 구현 경로, 별도 주식 저장소의 제안 `tests/test_live_activation_gate.py`, 운영 설정 예제 및 `docs/operations/` 인수인계. 실제 키/계좌 값은 Git에 보관하지 않는다.
- **할 일:** 승인 전에는 활성화 체크만 수행하는 dry run과 실행 게이트를 구현한다. 사용자에게 검토 가능한 계좌·전략·한도·기간·수동 중지/재개 절차와 검증 결과를 제시한다. 별도 명시 승인 이후에만 정해진 범위로 활성화한다. 과거 예산 언급이나 "구현 시작"을 실거래 승인으로 해석하지 않는다.
- **검증:** 미설정/만료/철회/초과 정책 거부, 계좌 불일치·미해결 주문·패치/복원 실패 시 차단, 운영 중 독립 중지와 사용자 직접 브로커 접근을 확인한다. 실제 거래를 했을 때는 원장과 증권사 결과를 대사하고 자동 범위 확대를 금지한다.
- **완료 증거:** 승인 범위 참조, 검증 통과/미검증 목록, 활성화 시각·설정 버전·원장 대사·중지 확인. 승인이 없으면 dry run 완료만 기록하고 이 카드는 활성화 완료로 표시하지 않는다.
- **차단 범위:** 명시 승인·운영 필수값·실환경 검증이 없으면 실제 활성화는 차단된다. 준비 코드와 합성 게이트 테스트는 계속 진행할 수 있다. 출금·송금·무제한 매매·전략/위험 한도 자체 변경은 허용하지 않는다.
