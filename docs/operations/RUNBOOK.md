# MinyQuant 운영·복구 준비

향후 운영 명세이며 현재 배포·계좌 연결·실거래는 활성화하지 않았다. 실제 장비 접속·변경은 해당 작업 범위에서 별도로 수행한다.

## 활성화 전

- 증권사·시장·계좌·전략·금액/손실/노출/환전 한도·위임 기간, 데이터 이용 조건과 지연 여부를 확정한다. 미정한 값은 합성 자료·fake 시험을 막지 않는다.
- 서비스 계정·비밀 저장소·DB 접근권한을 MinyAI와 분리한다. LLM/연구 프로세스에는 주문 키를 주지 않는다.
- 정책/스키마/코드/데이터 버전과 수용시험 결과를 고정한다. 시간·시세·환율·계좌 신선도, 독립 브로커 접근, 경보 전달을 확인한다.
- 주식 서비스는 서버에 금융 DB/실행부를, 필요시 메인 GPU 장비에 연구 worker를 둘 수 있다. 실제 배치는 가용 자원·기존 서비스·복원 시험 후 결정한다.

## 중지와 재개

UNKNOWN·계좌 불일치·손실 한도·키 침해·원인불명 종료에서는 영속 안전 중지 latch와 신규 위험 확대 차단을 유지한다. 예약금은 확인 전 풀지 않는다. 중복·역순 이벤트를 처리하며 주문/체결/현금/포지션/수동 거래/환전까지 전체 조회·대사한다.

사고 latch는 날짜 변경·재시작·대사 성공만으로 해제하지 않는다. 원인 해소와 사용자 재승인 후 재개한다. 정상 계획 재시작은 사전에 승인된 운영 주체가 기록하고 유효한 위임·대사·건강·신선도·안전 중지 없음 조건을 모두 확인한다. 상세 규칙은 [설계](../design.md)를 따른다.

## 백업과 복원

1. 신규 주문을 중지하고 소유자·버전·복원 지점·진행 중/UNKNOWN 상태를 기록한다.
2. 지원되는 DB 일관 백업을 독립 저장소에 암호화 보관한다. 키 복구 수단은 별도 보호한다. 살아 있는 DB 파일을 임의 복사하지 않는다.
3. 별도 격리 환경에서 복호화·스키마·계정/권한·원장 일관성을 검사한다. 두 executor를 동시에 활성화하지 않는다.
4. 실제 외부 효과가 있었다면 이전 DB만 복원해 재주문하지 않고 브로커 전체 조회·대사로 상태를 맞춘다. UNKNOWN과 사고 latch는 보존한다.
5. 복원 시간·유실 범위·PITR 필요성을 실제 시험하고 RPO/RTO를 확정한다. 로컬 디스크 동기 쓰기를 디스크 손실 시 RPO 0으로 간주하지 않는다.

LUKS 해제·시각 동기화·DB 복구·비밀 주입·정책 검증·대사 순서를 실제 배포 환경에서 검증한다. 같은 물리 서버의 MinyAI/OpsLoop 서비스는 임의로 중단하거나 변경하지 않는다. MinyAI RUNBOOK은 공용 장비 조정 기준이고 금융 내부 복원/재개 정본은 이 문서다.
